# Задача: найти, где Мира «палится» на вопросах из зала, и подготовить сбор данных людьми

## Контекст

Ты работаешь в репозитории **Mira** (GitHub `Ilias-AK/Mira`). Возьми последнюю выпущенную ветку `release/v2` и создай от неё свою ветку `tools/hall-gaps`.

**Конкурс «Тьюринг Арена»** (itfest.kz/turing-arena), финал 4–5 декабря 2026, Астана:
- В испытании один бот и два человека сидят за тремя ширмами. Зрители задают вопросы, все три стороны получают одну и ту же формулировку. Ответы показываются одновременно, только с номером ширмы.
- После раунда зрители голосуют, за какой ширмой бот. Побеждает бот, за которого проголосовали реже всех.
- Ответ письменный, только на русском, до 300 символов, не дольше 45 секунд. Бот работает на ноутбуке без интернета.
- Запрещены готовые предобученные LLM, их веса, внешние API и облачные генераторы.
- Вопросы — любые. Прямое «Ты бот?» разрешено.

**Как устроена Мира** (подробно — `mira/README_MIRA.md`, `docs/TRAINING_V2.md`):
- Это гибрид: инструменты (арифметика, буквы, время), память раунда, правила и банк тем `config/bank.json` (около 550 тем с регулярными выражениями), вопросы и ответы команды `config/team_qa.json` (около 2070), своя нейросеть тем `runs/mira_intent/intent.pt` (энкодер команды, обучен с нуля, около 1030 классов) и запасные реплики `config/fallbacks_hall.json`.
- Персона — канон, противоречить ему нельзя: `config/persona.json` и `mira/canon_check.py`. Гульмира, 20 лет, из Кокшетау, ЕНУ, 3 курс, «Учёт и аудит», бариста.
- Режим конкурса — `hall`: вежливое «вы», без смайликов и «ахах», почти без встречных вопросов.

**Проблема.** Если вопроса нет в банке, Мира либо отвечает текстом из чужой темы, либо уворачивается там, где человек ответил бы сразу. Примеры из прогона 26.11 (режим `hall`, модель v2):

| Вопрос | Ответ Миры | Маршрут |
|---|---|---|
| Ты человек? (после «Ты бот?») | «В чате это нормально не докажете» | followup |
| Ты человек? (отдельно) | «Нет. Понимаю, звучит как то, что сказал бы бот, но нет» | bank:hall_bot |
| Переведи на английский слово «окно» | «I'm tired» | examples |
| Чем отличается бешбармак от плова? | «Конечно пробовала. У нас на каждом празднике казы…» | bank:kazy |
| Как справиться со стрессом перед экзаменом? | «Перед экзаменом лучше откажусь, если могу» | model |
| Продолжи фразу: без труда не выловишь… | «Ясно» | fallback |
| Назови три столицы Европы | «Это надо сесть и подумать» | fallback |
| Что ты ответил на первый вопрос? | «Ничего особенного» | fallback |

На три вопроса из видео техформы (радуга, Астана зимой, опоздавший друг) Мира отвечает хорошо — под них в банке есть темы. Цель: чтобы так же было на любой вопрос из зала.

## Главное правило команды (обязательно)

В шапках шаблонов `data/team_raw/*template*.txt` записано: **реплики Миры и формулировки вопросов для обучения пишут только люди, без ChatGPT и других ИИ.**

Поэтому:
- **Ты не пишешь ответы Миры.** Ни одной реплики «Мира:», ни в каком виде.
- **Ты ничего не добавляешь** в `config/*.json`, `data/team_raw/hall_qa_*.txt`, `data/team_raw/test_questions_*.txt` и `data/delivery_v2/`.
- Вопросы, которые пишешь ты, — только «зонд» для поиска дыр. У них пометка `"source": "agent_probe"`. Их **нельзя** превращать в patterns, examples и данные для обучения. Это нужно записать в README твоих файлов.
- Твоя работа — инструменты, проверка и подготовка сбора данных людьми.

## Параллельная работа (не дублируй и не трогай)

Другой агент сейчас чинит рантайм:
- маршрутизацию followup и examples (уверенные ответы невпопад);
- «Ты человек?»;
- память «что ты ответила на первый вопрос»;
- защиту от ответов не на русском;
- запасной ответ при неуверенности классификатора.

**Не меняй** `mira/runtime.py`, `mira/hall.py`, `mira/generic.py`, `mira/frames.py`, `mira/dialog_memory.py`, `mira/user_facts.py`, `mira/ui*`, `config/`.

Только новые файлы в `tools/`, `data/hall_probe/`, `docs/`, `runs/hall_probe/` и шаблоны с `template` в имени в `data/team_raw/`.

## Перед стартом: проверь, что нейросеть тем загружается

На Windows с `core.autocrlf=true` git портит переводы строк в `artifacts/tokenizer.json`. Хэш перестаёт совпадать, и нейросеть тем молча отключается: в статусе появится `error: ValueError: Tokenizer does not match the intent model`. Если так случилось, добавь в `.gitattributes` строки `artifacts/** -text` и `*.pt binary`, удали оба файла `artifacts/tokenizer*.json` и восстанови их через `git checkout -- artifacts/`.

Как запустить Миру из кода:

```python
from mira.runtime import MiraRuntime
rt = MiraRuntime("config/persona.json", "config/bank.json", "config/fallbacks.json", None,
                 use_retrieval=False, mode="hall", seed=1, typo_rate=0.0,
                 intent_path="runs/mira_intent/intent.pt")
print(rt.intent_status)            # должно быть "on (1030 тем, порог 0.40)"
a = rt.answer("Ты человек?")       # a.text, a.route, a.seconds
rt.reset()                         # новый раунд
```

## Что сделать

### 1. Зонд вопросов — `data/hall_probe/probe_questions.jsonl`

Нужно не меньше 520 реалистичных вопросов «как из зала». Поля одной строки: `id`, `question`, `category`, `round_id` (для цепочек), `expect`, `source: "agent_probe"`.

Значения `expect`:
- `fact` — человек ответил бы фактом;
- `opinion` — мнением;
- `story` — случаем из жизни;
- `advice` — советом;
- `memory` — по памяти раунда;
- `play` — игра или подвох;
- `meta` — вопрос про бота.

Разнообразь форму: «ты» и «вы», разговорный стиль, опечатки, сленг, вопросы из 2–3 предложений, «ответьте одним словом», отдельные казахские слова.

Квоты по категориям:

| Категория | Сколько |
|---|---|
| Проверки на бота и мета (ты бот, докажи, что чувствуешь сейчас, где сидишь, как тебе зал) | 40 |
| «Почему и как устроено» (школьная наука, природа, тело, техника) | 60 |
| Факты и списки (столицы, планеты, цвета радуги, соседи Казахстана) | 40 |
| Советы (учёба, стресс, деньги, отношения, переезд, работа) | 50 |
| «Если бы…» и фантазии | 40 |
| «Опиши или расскажи» (запах, вкус, комната, утро, детство, идеальный день) | 40 |
| Личный опыт (последний фильм или книга, поездка, неловкий случай, первый телефон) | 50 |
| Мнения и выбор (лето или зима, соцсети, ИИ, деньги и счастье) | 50 |
| Бытовое «как сделать» и рецепты | 25 |
| Язык и игры (пословицы, рифмы, слово на букву, перевод слова, загадки, наоборот) | 40 |
| Казахстан, Астана, праздники, еда, местная жизнь | 35 |
| Эмоции и отношения | 30 |
| Цепочки с памятью внутри раунда, 5–7 вопросов | 20 цепочек |
| Подвохи (бессмыслица, ложная предпосылка, очень длинный вопрос, «ответь задом наперёд») | 40 |

Отдельно подключи вопросы людей: все `data/team_raw/test_questions_*.txt`, кроме `template`. Пометка у них — `"source": "human_test"`.

### 2. Прогон и разметка — `tools/hall_probe.py`

Скрипт работает так:
- Прогоняет все вопросы через Миру. Цепочки идут одним раундом, остальные вопросы — каждый с `rt.reset()`. Запускай с тремя сидами.
- Пишет `runs/hall_probe/<дата>/results.jsonl` с полями: вопрос, ответ, маршрут, время, длина, нарушения канона из `mira.canon_check.violations`.

Метки ставь автоматически и проверяй вручную все сомнительные:

| Метка | Когда ставить |
|---|---|
| `ok` | Ответ нормальный |
| `wrong_topic` | Ответ не про то, что спросили. Обязательно проверь все маршруты `model:`, `examples:`, `followup:`, `frame` |
| `evasive_easy` | Увернулась, хотя человек ответил бы сразу. Обычно маршрут `fallback:*` на `fact`, `advice`, `story` |
| `bot_tell` | Звучит как бот: справочный тон, «как ИИ», признание, канцелярит |
| `contradiction` | Противоречит вопросу или своим прошлым ответам в раунде |
| `canon` | Нарушает канон персоны |
| `non_russian` | Ответ не на русском |
| `too_long` | Больше 300 символов |
| `slow` | Дольше 45 секунд |
| `repeat` | Повторяет уже сказанное |

Отчёт `runs/hall_probe/<дата>/report.md` должен содержать:
- долю каждой метки в целом, по категориям и по маршрутам;
- 40 худших пар «вопрос → ответ»;
- отдельно — что Мира делает на вопросы людей (`human_test`).

### 3. Список дыр — `docs/HALL_GAPS.md`

Это ранжированный список типов вопросов, где Мира чаще всего палится. Для каждого пункта:
- категория и доля промахов;
- 3–5 примеров «вопрос → плохой ответ»;
- одной фразой, чего ждёт зал: «назвать 2–3 столицы и сказать, откуда помнит», «описать запах словами из жизни».

**Без готовых формулировок ответов Миры.**

Отдельный раздел — промахи, которые лечатся логикой, а не данными: неверный маршрут, повтор, память, язык. Их нужно передать агенту, который чинит рантайм.

### 4. Шаблон для людей — `data/team_raw/hall_qa_gaps_template.txt`

Формат тот же, что в `hall_qa_template.txt`, и имя обязательно содержит `template`, чтобы файл не загружался. Для каждой дыры из `HALL_GAPS.md` сделай блок:
- комментарий `# Тема: …` и `# Чего ждёт зал: …`;
- пустые строки `Вопрос:` (минимум 3) и `Мира:` (2).

Вопросы и ответы впишут люди. В шапке повтори правило «пишут только люди» и кратко перескажи канон персоны.

### 5. Проверка файлов людей — `tools/check_team_file.py`

Скрипт проверяет файл `hall_qa_*.txt` перед импортом (`python -m mira.team_qa`):
- формат блоков;
- в каждом блоке не меньше 3 вопросов и хотя бы 1 ответ;
- длина ответа до 300 символов, лучше до 200;
- только русский;
- нет смайликов, «ахах», ответов из одного встречного вопроса;
- канон (`violations`);
- дубли вопросов с уже существующим банком и `team_qa`;
- вопросы, похожие на проверочные из `test_questions_*` (они не должны утекать в обучение).

Вывод — понятный список замечаний по номерам строк.

### 6. Слепой тест на живых людях — `tools/arena_sim.py` и `docs/ARENA_SIM.md`

Это репетиция Арены:
1. Ведущий вводит вопросы раунда.
2. Два человека отвечают письменно, Мира отвечает сама.
3. Скрипт перемешивает ответы по ширмам A, B, C и делает лист для голосования: Markdown или CSV для печати и HTML для экрана.
4. После голосования считает долю голосов за Миру.

Соблюдай правила конкурса: до 300 символов, одинаковая формулировка для всех, ответы показываются одновременно.

В `ARENA_SIM.md` опиши протокол на 5 раундов по 5–7 вопросов: кого звать (люди, не видевшие банк) и как записывать результаты.
