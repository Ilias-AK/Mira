# Тьюринг-арена

Локальная русскоязычная система: поиск реплик, память разговора и собственный генератор с копированием. Веса и токенизатор обучаются с нуля. Код не вызывает внешнюю модель.

**Статус на 21 ноября 2026:** основная модель обучена на RTX 3050, но часто отвечает не по теме и повторяет факты анкеты. Пилот с отключением части анкет и перестановкой их фактов не улучшил ответы; его веса не рекомендованы для основного чата. Разбор сохранён в `artifacts/persona_pilot_audit/RESULT.txt`. Инженерный конвейер, корпус и полный поисковый кэш готовы; качество конкурсной модели пока не достигнуто. Маленькие контрольные модели в `runs` проверяют код и не предназначены для конкурса; в переносимый пакет они не входят.

**Следующее обучение:** пакет `training-v2-kit.zip` и инструкция `TRAINING_V2.txt` предназначены для уже установленного проекта друга. В нём расширенный языковой корпус, отобранные диалоги, исправленное покрытие текста при обучении, настройка долей источников и сохранение промежуточных версий. Это подготовленный эксперимент; улучшение общения ещё нужно измерить после обучения на Lenovo. Отдельный патч сохранения устанавливать не требуется. Команды ниже описывают первоначальную установку; для продолжения используйте `scripts/train_v2_lenovo.ps1` по новой инструкции.

## Быстрый запуск на Lenovo друга

Требуются Windows, Python 3.11, актуальный совместимый драйвер NVIDIA, около 20–40 ГБ свободного места. Во время установки и получения данных нужен интернет; чат после подготовки работает локально.

Откройте PowerShell в распакованной папке проекта:

```powershell
& .\scripts\bootstrap_lenovo.ps1
& .\.venv\Scripts\python.exe -m arena.doctor --require-cuda
```

Если Windows блокирует запуск неподписанного `.ps1` из скачанного архива, можно выполнить конкретный скрипт в отдельном процессе:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\bootstrap_lenovo.ps1
```

Так же запускаются `train_lenovo.ps1` и `chat.ps1`; параметры скрипта ставятся после пути. Это не меняет постоянную политику PowerShell.

Скрипт создаёт отдельную `.venv`, устанавливает точную CUDA-сборку PyTorch 2.10.0 и зависимости. По умолчанию используется CUDA 12.6; `-Cuda cu128` выбирает другую официальную сборку. Установка драйвера не выполняется автоматически. [Официальные варианты PyTorch](https://pytorch.org/get-started/previous-versions/#v2100).

Если получен пакет с готовыми `data/processed` и `artifacts`, повторно готовить их не нужно. В исходном репозитории без данных:

```powershell
& .\scripts\prepare_data.ps1
```

Сначала измерить реальную модель на GPU:

```powershell
& .\.venv\Scripts\python.exe -m arena.benchmark --minutes-per-size 10 --output artifacts/lenovo_benchmark.json
```

Три прогона по 10 минут, прогрев и декодирование. Измеряются настоящие `ArenaModel` small/main/large, копирование и gate поиска. Случайные токены дают оценку вычислений; реальная скорость загрузчика и качество русского измеряются отдельно. При OOM повторить нужный размер с `--sizes main --batch-size 2`.

Запуск основной модели:

```powershell
& .\scripts\train_lenovo.ps1 -RunName main -Preset main
```

По умолчанию: языковой этап до 12 часов / 12 000 обновлений, затем диалоговый до 18 часов / 16 000 обновлений; останавливается по первому достигнутому пределу. Microbatch 4, accumulation 8. Это первоначальный бюджет, который корректируется по бенчмарку и валидации, а не обещание качества за указанное время.

Перед диалоговым этапом скрипт проверяет поисковый кэш для **всех 146 974 диалоговых записей train и val**. Если полный кэш уже есть в пакете, выполняется только проверка его совместимости: поиск повторно не запускается. Обучение читает найденные примеры из SQLite. Если кэша нет, скрипт создаст его; эта CPU-подготовка может занять часы. Прерванное построение продолжается автоматически, незавершённый кэш не допускается к обучению. `-CacheWorkers 2` снижает нагрузку при построении. Ноутбук во время обучения должен быть подключён к питанию и не переходить в сон.

Кэш можно заранее рассчитать на любом компьютере с установленными зависимостями:

```powershell
& .\scripts\prepare_retrieval_cache.ps1 -Workers 4
```

После успешного завершения перенесите `artifacts/retrieval_cache.sqlite3` вместе с теми же данными и индексом, либо соберите архив с `--with-cache` по инструкции внизу. Упаковщик проверяет все записи кэша, исключение текущего диалога и соответствие кандидатов train-индексу. Для новых данных или изменённого ранжировщика нужен новый кэш: утилита отклонит несовпадающие SHA256 вместо незаметного смешивания версий.

После остановки:

```powershell
& .\scripts\train_lenovo.ps1 -RunName main -Resume
```

`-Resume` восстанавливает веса, AdamW, AMP scaler, генераторы случайных чисел и позицию в данных. `-LanguageHours` и `-DialogueHours` — **суммарные бюджеты этапов с учётом уже прошедшего времени**, `Steps` — суммарные целевые номера шагов. Для продолжения уже законченного этапа увеличьте соответствующий бюджет. Для изменения microbatch или размера модели используйте новый `RunName`; это не побитное продолжение старого опыта.

Если памяти мало, новый запуск:

```powershell
& .\scripts\train_lenovo.ps1 -RunName main_b2 -BatchSize 2 -Accumulation 16
```

Чат с поисковым резервом доступен до обучения:

```powershell
& .\scripts\chat.ps1
```

После полноценного обучения:

```powershell
& .\scripts\chat.ps1 -Checkpoint runs/main/dialogue/best.pt
```

`/reset` начинает новый раунд, `/quit` завершает чат. В stdout выводится ответ; внутренние диагностические поля не добавляются к реплике. Веса и токенизатор должны соответствовать по SHA256.

## Как проходит вопрос

1. Сохраняется точная формулировка и извлекаются подходящие определения и явные факты из памяти.
2. Проверяемая локальная операция может выполнить арифметику, работу с буквами или буквальное извлечение определения.
3. BM25 по словам и символьным триграммам находит контексты из train. Дополнительный обучаемый ранжировщик доступен для экспериментов.
4. Проверяются известные явные противоречия. Один подходящий пример, история, персона и память поступают в encoder–decoder.
5. Модель выбирает между токеном своего словаря и копированием позиции входа. Отдельный gate регулирует использование найденного примера.
6. Проверяются длина и повторы. Если генерация не закончилась или ответ не прошёл проверку, используется заранее найденный резерв; последний технический резерв — одна короткая просьба уточнить вопрос.

Генератор живёт в отдельном процессе: зависший процесс можно остановить, не потеряв поисковый ответ. Поиск тоже имеет временной бюджет. Эти ограничения проверены в тестах; задержки Windows/CUDA и отключение сети ещё проверяются на конкурсном ноутбуке.

Память не является универсальным логическим анализатором. Она хранит исходные реплики и узкий набор явных фактов, разделяет пользователя и бота, сохраняет определения новых слов. Сложные отрицания, убеждения людей и необычные условия требуют обучения и испытаний.

## Данные и масштабирование

Подготовленный набор содержит:

| Часть | Диалоговые примеры | Фрагменты Wikipedia | Всего |
|---|---:|---:|---:|
| train | 139 458 | 91 616 | 231 074 |
| val | 7 516 | 5 460 | 12 976 |
| test | 7 558 | 4 459 | 12 017 |

Обработано около 200 млн символов Wikipedia. Готовые JSONL занимают около 545 МБ. Токенизатор ByteLevel BPE, 8 192 токена, обучен только на train; 239,4 млн обработанных символов. Неизвестные русские слова и emoji не превращаются в UNK.

`source`, `id` и `group_id` — технические ключи. В текст реплик никаких дополнительных пометок не добавляется. Новые диалоги на этом этапе не генерировались. Исходные README/LICENSE находятся рядом со скачанными файлами.

Конвейер сохраняет целые диалоги/деревья/статьи в одной части, удаляет точные нормализованные дубликаты, восстанавливает OASST по родительским связям и фильтрует его исходные флаги. Поиск никогда не индексирует val/test. В диалоговом обучении из поиска исключается текущий `group_id`.

Общий узкий фильтр убрал 95 непригодных ответов с явной бранью, графическим насилием, контактами или характерными представлениями помощника. Он применяется также при построении поиска и выдаче. Это не заменяет ручную проверку естественности и уместности ответов.

Для расширения до всех 21 файла русской Wikipedia:

```powershell
& .\scripts\prepare_data.ps1 -WikiShards all -MaxWikiChars 0
```

`0` снимает лимит объёма, но не увеличивает автоматически GPU-бюджет. Увеличение корпуса требует повторной подготовки токенизатора/индекса и нового обучения; существующие несовместимые checkpoint не загрузятся. Можно оставить ограниченный срез через `-MaxWikiChars 400000000`. Загрузки возобновляются, обработка потоковая. `-WithoutToloka` создаёт вариант без этого источника.

Проверка подготовленных файлов:

```powershell
& .\.venv\Scripts\python.exe -m arena.data validate --output-dir data/processed
```

Она проверяет схему, хеши, группы, точные дубликаты и исходные префиксы говорящих. Это не доказательство отсутствия всех смысловых перефразировок и не оценка качества каждого текста.

## Модель и обучение

| Preset | Параметры при словаре 8192 | Encoder / decoder | Ширина |
|---|---:|---:|---:|
| small | 9 889 794 | 4 / 4 | 256 |
| main | 20 536 322 | 4 / 4 | 384 |
| large | 42 340 354 | 5 / 5 | 512 |

Общие входные/выходные эмбеддинги; основной контекст 512 токенов, ответ до 96. Formatter резервирует место вопросу, памяти и примеру. Языковой этап использует только текстовые записи Wikipedia и чередует продолжение текста с восстановлением отсутствующего фрагмента. Диалоговый этап учится на следующих репликах и реальных найденных примерах; часть поиска отключается. Текущий ответ никогда не извлекается в память до обучения на нём.

Экспериментальный ранжировщик обучен на 2 816 примерах с автоматически подобранными отрицательными парами. Ручная инспекция десяти новых вопросов не показала явного улучшения, поэтому в комплекте он **отключён** (`enabled: false`). Базовый поиск по этим вопросам: медиана около 0,25 с, максимум около 0,51 с на локальном CPU. Это измерение задержки, не человеческой неотличимости; резерв иногда отвечает мимо вопроса. Для усиления нужны оценки реальных найденных ответов людьми. Формат дополнительной разметки:

```json
{"query":"вопрос","candidate_id":"id записи индекса","label":1,"split":"train"}
```

```powershell
& .\.venv\Scripts\python.exe -m arena.retrieval fit-reranker --index artifacts/retrieval --labels ratings.jsonl
```

Обычный `fit-reranker` сохраняет веса выключенными. `--enable` явно включает новую версию; делать это следует после сравнения на отложенных разговорах. Изменение файла требует нового кэша и нового диалогового этапа через `--init-from`, а не продолжения старого опыта.

Состояния этапов лежат в `runs/<RunName>/language` и `dialogue`. `last.pt` — возобновление, `best.pt` — минимум валидационной ошибки. Валидационная ошибка не определяет лучшую конкурсную модель: окончательный выбор делается по целым разговорам с людьми. `metrics.jsonl` содержит loss, скорость по целевым и всем обработанным непустым токенам, время и шаги.

В новых запусках ограниченная проверка использует фиксированную перемешанную выборку из всего val. При стандартных настройках её 80 записей охватывают 76 диалогов или 73 статьи; последовательные первые 80 охватывали только 8 диалогов или 7 статей. Выборка одинакова между проверками и после resume, поэтому значения loss сопоставимы. Старые checkpoint автоматически сохраняют прежний последовательный порядок; явная смена порядка при resume отклоняется. Полноценный отложенный test остаётся отдельной финальной проверкой.

Ctrl+C не запускает следующий этап. Повторный запуск без `--resume` не перезаписывает существующие checkpoint. `--init-from` загружает только веса для нового этапа и сбрасывает оптимизатор/счётчики. При возобновлении проверяются хеши данных, токенизатора, индекса, ранжировщика и подпись настроек кэша. В кэше из кандидатов заранее исключается вся группа текущего примера; test не участвует ни в индексе, ни в кэше.

## Проверка и слепые раунды

```powershell
& .\.venv\Scripts\python.exe -m pytest -q
```

Тестируются копирование, причинность decoder, отсутствие скрытого обхода gate, переобучение маленькой модели на контрольном наборе, возобновление, отсутствие утечки групп, память, тайм-аут процесса и голосование. Маленькие тестовые наборы служат только проверке реализации.

При подготовке комплекта прошли **99 тестов на CPU**. Проверены также загрузка полного корпуса, короткое обучение и resume, один forward/backward основной модели с 20,5 млн параметров и 13 технических вопросов через отдельный процесс генерации. Все шесть точных проверок инструментов/памяти прошли; пустых ответов и превышений длины не было. Подробности — `artifacts/verification.json`. CUDA, длительный прогон и оценка людьми ещё не выполнены.

Для автоматического прогона файл вопросов имеет вид:

```json
{"rounds":[{"id":"round-1","turns":[{"question":"Первый вопрос"},{"question":"Уточнение"}]}]}
```

```powershell
& .\.venv\Scripts\python.exe -m arena.evaluation run --rounds rounds.json --checkpoint runs/main/dialogue/best.pt --output runs/evaluation.json
```

В комплекте есть `configs/technical_rounds.json`: арифметика, буквы, буквальное воспоминание и несколько свободных вопросов. Подставьте его вместо `rounds.json` для технической проверки. Эти вопросы не используются как обучающие диалоги.

Флаги `--no-retrieval` и `--no-memory` позволяют проверить вклад компонентов. Автоматический отчёт считает технические нарушения; человеческую неотличимость он не измеряет.

Для слепого сравнения подготовьте ответы двух людей в том же формате, добавив `answer` к каждому вопросу:

```powershell
& .\.venv\Scripts\python.exe -m arena.evaluation blind-pack --bot runs/evaluation.json --human-a human_a.json --human-b human_b.json --output public_rounds.json --private-key private_key.json
```

Публичный файл содержит только одинаковые вопросы и три номера с ответами. Позиция бота случайна и постоянна внутри раунда. Ключ не показывается зрителям. Голоса — JSON-массив `round_id, viewer_id, booth`; повторные голоса одного зрителя в раунде отклоняются:

```powershell
& .\.venv\Scripts\python.exe -m arena.evaluation tally --private-key private_key.json --votes votes.json --output vote_results.json
```

Основной показатель — доля верно указавших бота после серии. Не выводите из маленькой выборки вероятность первого места.

## Перенос другу

```powershell
python -m arena.bundle build --output dist/lenovo-kit.zip --with-data --with-cache
python -m arena.bundle verify dist/lenovo-kit.zip
```

Вариант `--with-data --with-cache` содержит код, инструкции, готовые данные, токенизатор, индекс и полный кэш. Отсутствующий, незавершённый или несовместимый кэш останавливает упаковку. Архив исключает `.venv`, исходные крупные загрузки, личные настройки и тестовые checkpoint. Встроенный manifest содержит размеры и SHA256; проверка читает содержимое архива. После распаковки достаточно установки окружения, бенчмарка и запуска обучения; поиск по обучающим примерам повторно не нужен. Интернет для инференса не требуется. Вариант без `--with-cache` оставляет расчёт кэша принимающему компьютеру.
